# 超级员工 (The Cognitive Editorial) PRD
## 1. 产品概述

**产品名称**: 超级员工助手 (The Cognitive Editorial)
**产品定位**: 企业级 AI 智能办公助手桌面端Web应用。
**目标用户**: 企业内部员工（如研发、市场、销售、HR等各部门员工）。
**核心价值**: 通过自然语言交互，帮助员工一站式解决企业内部高频办公事务（报销、会议室预定、请假、排期排障、查阅规章制度及人员信息等），极大提升办公效率与体验。

## 2. 核心功能模块

### 2.1 登录模块

- **账号密码登录**: 使用企业内部账号及密码进行登录验证，确保企业数据安全及账号体系正常使用。

### 2.2 角色与权限

系统按角色划分为三个层级，权限由高到低依次为：

| 角色 | 权限级别 | 说明 |
|------|----------|------|
| 管理层 | 最高 | 可查看全员信息、所有审批记录及团队数据；通讯录展示完整信息（含手机号、邮箱） |
| HR | 最高 | 与管理层同级，可查看全员假期、薪资及人事相关数据；通讯录展示完整信息 |
| 普通员工 | 基础 | 仅可查看本人相关数据及公开信息；通讯录中敏感字段（手机号等）按脱敏规则展示 |

> 管理层与 HR 权限等级相同，但数据范围有所侧重：管理层侧重团队业务数据，HR 侧重人事与薪酬数据。具体数据权限边界待后续详细设计阶段确认。

**权限双层校验机制**：

系统在展示层与服务层同时执行权限校验，两层缺一不可：

- **展示层（前端）**：根据当前登录角色，隐藏或脱敏无权限字段，给用户提供符合角色的界面体验。
- **服务层（后端）**：所有涉及敏感数据的接口（通讯录详情、全员假期、审批记录等）在返回数据前，根据调用方身份 Token 再次鉴权，无权限字段在接口层直接过滤，不下发至客户端。前端展示状态不作为后端授权依据。

### 2.3 操作确认机制

凡涉及**写操作**（数据提交、状态变更、资源占用）的 Skill 卡片，均须在执行前触发二次确认，防止 AI 意图误判或用户误触导致不可逆操作。

**确认触发规则**：

| 操作类型 | 触发方式 | 确认内容 |
|----------|----------|----------|
| 报销提交 | 底部确认栏 | 展示事由、金额、归属，用户点击「确认提交」后方可发起 |
| 会议室预定 | 底部确认栏 | 展示会议室名称、时间段、参会人列表，确认后写入系统 |
| 请假申请 | 底部确认栏 | 展示假期类型、起止日期、扣减天数，确认后提交审批流 |
| IT 工单创建 | 内联确认按钮 | 展示工单摘要，用户主动点击「创建工单」触发，不自动提交 |

**确认交互规范**：
- 确认栏包含「确认提交」（主操作）和「取消」（次操作）两个按钮。
- 取消后回到卡片可编辑状态，已填写内容保留，不清空。
- 确认提交后，卡片进入「提交中」加载状态；服务端返回成功后切换为「已提交」只读态；失败则显示错误原因并允许重试。

### 2.4 导航与框架页
- **侧边栏 (Sidebar)**:
  - 品牌标识区（The Cognitive Editorial）。
  - **新建对话**: 快速重置上下文，开启新会话。
  - **导航菜单**: 
    - 个人知识库：进入用户私有文件及文档管理模块。
    - 历史记录：通过侧滑抽屉展示历史会话列表，支持点击查看历史对话详情。
  - **底部个人信息区**: 展示员工头像、姓名及入口级设置（占位）。

### 2.5 AI 智能对话 (Chat)
- **核心交互**: 提供类似主流大模型的聊天界面，包含欢迎语及快捷指令推荐。
- **快捷指令 (Quick Commands)**: 包含一键发送的预设请求（提交报销、预定会议室、请假申请、今日日程、IT报修、查通讯录、制度查询、审批进度等）。
- **消息流 (Message Feed)**: 
  - **用户消息**: 靠右对齐的淡紫色气泡，支持内嵌提及的上下文文档标签。
  - **AI 消息**: 靠左对齐的白底卡片式气泡，左侧带品牌色边框。支持展示纯文本及结构化富文本卡片（Card）。
  - **操作按钮**: AI 消息下方提供单行操作区，包含：复制、重新生成、点赞（Good）、点踩（Bad，带反馈弹窗）。
- **输入区 (Input Area)**: 
  - 附件能力：支持点击「+」号上传图片、上传文件、或从「个人知识库」中选取文件作为本次对话的上下文。
  - 多文档上下文池：选择的知识库文档将在输入框上方显示为标签（Chip），并可设置「绕过（Bypass）」状态以排除特定文档。

### 2.6 办公场景技能 (Mock Skills)
AI 可识别用户意图并直接在对话流中渲染出结构化的可交互卡片（UI 组件）。所有涉及写操作的卡片均遵循 2.3 节定义的操作确认机制。

1. **报销管理 (`expense`)**: 展示报销审批进度时间轴；支持直接通过表单卡片填写报销事由、日期、归属并上传发票，经确认后提交。
2. **会议预定 (`meeting`)**: 识别时间人数意图，展示可用的会议室列表卡片，支持一键预定及添加参会人，经确认后写入系统。
3. **请假申请 (`leave`)**: 呈现员工当前的各类假期余额概览，内嵌请假申请表单（日期、事由选择），经确认后提交审批流。
4. **日程管理 (`schedule`)**: 以时间轴形式列出当日日程节点，高亮当前正在进行的会议/任务。
5. **IT 服务 (`it`)**: 匹配到报修/VPN等关键词时，展示 IT 服务工单预填卡片及自助排障建议文档，用户主动点击「创建工单」后经确认提交；支持一键转人工。
6. **通讯录查询 (`contact`)**: 提取对话中的人名，返回该员工的详情卡片（部门、职位、手机号、工位等），展示字段依当前用户角色权限决定（服务层与展示层双重校验）；并提供一键拨号或发消息按钮。
7. **基于文档的 Q&A (`doc-qa`)**: 当存在选中的知识库文档时，AI 回答将默认基于这些文档内容进行摘要和信息提取。

### 2.7 审批进度查询

用户可通过快捷指令或自然语言（如「查我的报销进度」「看一下请假申请状态」）触发审批进度查询，AI 返回对应的状态卡片。

**状态流转与展示**：

| 状态 | 展示样式 | 说明 |
|------|----------|------|
| 审批中 | 黄色标签 | 已提交，等待审批人处理 |
| 已通过 | 绿色标签 | 审批完成，操作生效 |
| 已驳回 | 红色标签 | 审批不通过，展示驳回原因 |
| 已撤回 | 灰色标签 | 用户主动撤回，操作取消 |

**驳回场景处理**：
- 状态卡片在「已驳回」状态下，需展示审批人填写的**驳回原因**（不可为空，由审批系统强制要求）。
- 卡片提供「重新申请」快捷操作，点击后以原申请内容为预填项，创建新的申请卡片，用户可修改后重新提交（同样经过操作确认机制）。
- 驳回记录在历史查询中长期保留，不可删除。

### 2.8 个人知识库 (Knowledge Base)
- **文档列表**: 列表展示用户上传的私有文档文件，显示名称、大小、上传时间及解析状态（如 OCR 成功）。
- **搜索与筛选**: 支持针对文档名称的即时模糊搜索。
- **操作**: 
  - **上传**: 本地选取新文件上传至知识库（Mock 进度条体验）。
  - **问答**: 在文档列表中点击某篇文档的「问答」按钮，可自动将其设为上下文并跳转至 Chat 视图开始基于该文档的新对话。
  - **预览/删除**: 基础的文件管理操作。

### 2.9 历史记录 (History)
- **触发方式**: 侧边栏导航点击。
- **展示形式**: 屏幕右侧滑出悬浮抽屉（Drawer）。
- **内容列表**: 按照时间倒序展示历史会话列表（标题、时间）。
- **加载会话**: 点击列表项可关闭抽屉，清空当前聊天区并复现该历史会话的完整聊天记录内容。
